# Jogo25D.Core – Arquitetura do Sistema de Combate, Itens e Efeitos

Este documento descreve a arquitetura atual do sistema de:

- Combate
- Itens
- Inventário
- Armas (melee e ranged)
- Projéteis
- Buffs e Effects
- Banco estático de itens (ItemDB)

---

# 1. Visão Geral da Arquitetura

O sistema é dividido em três camadas principais:

## 1. Definitions (Definições)

São modelos estáticos que descrevem comportamento e dados base:

- `ItemDefinition`
- `WeaponDefinition`
- `EffectDefinition`

Essas classes **não armazenam estado de runtime**, apenas regras e configurações.

---

## 2. Instances (Estado em Runtime)

Representam objetos ativos no jogo:

- `ItemInstance`
- `EffectInstance`

Essas classes armazenam estado mutável:

- Cooldown restante
- Quantidade
- Tempo restante de efeito
- Expiração

---

## 3. Entidades Ativas

Objetos presentes na cena:

- `Player`
- `Projectile`

Eles utilizam Definitions + Instances para executar comportamento real.

---

# 2. Sistema de Dano

## DamageType

Define o tipo de dano:

- Physical
- Fire
- Ice
- Poison
- Electric
- True

## DamageInfo

Struct que encapsula informações do dano:

- Amount
- Type
- Source
- CritMultiplier

O Player processa o dano aplicando:

- Resistência por tipo
- Defesa física
- Redução final

---

# 3. Sistema de Effects

## EffectDefinition

Define o comportamento base de um efeito:

- Duration
- Apply()
- Tick()
- Remove()

Não guarda estado.

---

## EffectInstance

Guarda estado runtime:

- Tempo restante
- Se expirou
- Referência à definição

Fluxo:

1. Player recebe EffectDefinition
2. Cria EffectInstance
3. Aplica Apply()
4. Atualiza via Tick()
5. Remove ao expirar

---

## Exemplos implementados

### PoisonEffect
- Dano por segundo
- Usa acumulador interno de tick

### AttackBuffEffect
- Aumenta Attack ao aplicar
- Remove bônus ao expirar

---

# 4. Sistema de Itens

## ItemDefinition

Define:

- Id
- Name
- Type
- Stackable
- MaxStack
- Cooldown
- Use()

Não guarda estado.

---

## ItemInstance

Guarda:

- Quantity
- CooldownRemaining
- Referência à Definition

Responsável por:

- Controlar cooldown
- Controlar quantidade

---

# 5. Armas

## WeaponDefinition (base)

Contém:

- BaseDamage
- DamageType
- CritChance
- CritMultiplier
- SelfEffects
- OnHitEffects

Possui método interno `BuildDamage()`.

---

## MeleeWeaponDefinition

- Ataca jogadores próximos
- Usa Range
- Aplica dano direto
- Aplica OnHitEffects

---

## RangedWeaponDefinition

- Instancia Projectile
- Define Damage
- Define direção
- Aplica efeitos ao acertar
- Usa PackedScene

---

# 6. Projectile

Responsável por:

- Movimento
- Lifetime
- Detectar colisão
- Aplicar Damage
- Aplicar OnHitEffects
- Se destruir após impacto

Evita dano no próprio Source.

---

# 7. Inventário

Classe `Inventory` gerencia:

- Lista de ItemInstance
- Equipamento de arma
- Uso da arma equipada
- Atualização de cooldowns

Permite:

- Stack automático
- Equipamento simples
- Uso via Definition.Use()

---

# 8. Player

Responsável por:

- Vida
- Ataque
- Defesa
- Resistências
- Lista de EffectInstance
- Inventário

Atualizações por frame:

- Atualiza inventário
- Atualiza efeitos ativos

Possui:

- ReceiveDamage()
- AddEffect()
- GetAimDirection()

---

# 9. ItemDB

Banco estático de itens.

Função:

- Registrar definições únicas
- Servir como catálogo global
- Evitar recriação repetida

Contém:

- Espada básica
- Arco envenenado
- Cajado flamejante
- Poção de força

Inicialização preguiçosa (lazy initialization).

---

# 10. Fluxo Completo de Combate

Exemplo: Arco Envenenado

1. Player usa arma equipada
2. Definition cria Projectile
3. Projectile acerta alvo
4. Player alvo recebe DamageInfo
5. Player alvo recebe EffectDefinition
6. EffectInstance é criada
7. Tick executa dano ao longo do tempo
8. Effect expira e Remove() é chamado

---

# 11. Separação Conceitual Importante

| Conceito | Guarda Estado? | Pode ser compartilhado? |
|----------|----------------|--------------------------|
| Definition | Não | Sim |
| Instance | Sim | Não |
| Player | Sim | Não |
| ItemDB | Não | Sim |

---

# 12. Padrão Arquitetural Utilizado

O sistema segue o padrão:

Definition → Instance → Runtime

Esse padrão:

- Evita mistura de dados e estado
- Permite múltiplas aplicações simultâneas
- Facilita stacking futuro
- Permite efeitos dinâmicos
- Mantém sistema extensível
